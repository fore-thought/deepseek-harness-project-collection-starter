# 多角色流水线（pipeline-and-roles · 项目组级）

> 本文件 = 项目组级规范的第二份正文，与 `AGENTS.md` 同级，被各项目**只读引用**。
> 定位：**可选能力**。单会话流程（`AGENTS.md` §7 的四道闸）原样保留；只有把同一项目
> 拆成多个角色会话接力时才需要本文件。**读取方式（组级 AGENTS.md §5）：启用多角色时读；
> 单会话项目不必读。**
> 版本: v1.0 ｜ 建立: 2026-09-16 ｜ 变更记录见文末。

## 0. 什么时候用

- **单会话模式**（默认）：一个会话干完，走组级 `AGENTS.md` §7 的四道闸。本文件不影响它。
- **多角色模式**：同一项目开多个会话，各承担一个角色，通过单元文件夹接力。

启用判据：确实存在可并行的独立工作，且愿意接受「跨会话只能靠文档通信」的成本。
不满足就不启用——多角色不是更高级的形态，只是另一种取舍。

## 1. 三个角色

| 角色 | 预设 id | 中文显示名 | 写权：只写这些路径 | 其余 |
|---|---|---|---|---|
| 制作人 | `producer` | 制作人 | `process/docs/plans/`、`process/docs/progress.md`、`work-log.md`、`decisions.md`、`assumptions.md`、`measurements.md`、`process/docs/HANDOFF.md`、`process/docs/handoff/producer/`、`process/docs/units/*/brief.md` | 只读 |
| 实现者 | `implementer` | 实现者 | `outputs/`、`process/project/`、`process/docs/units/*/build*.md`、`process/docs/handoff/implementer/` | 只读 |
| 验收员 | `verifier` | 验收员 | `process/docs/units/*/accept.md`、`process/docs/handoff/verifier/` | 只读 |

- 上表出现的 `*` 是给人看的通配，**不是被执行或校验的规则**。
- **能读什么不需要声明**：工作区里的文件都能读。要声明的是**写哪儿**。
- **角色身份由预设的 persona 承载**——它在系统提示词层，每个请求重发、永不被裁剪，
  是我们能碰到的最高权威。没有用角色预设的会话按 §4 降级处理。

## 2. 单元文件夹 = 传送带

多角色的核心不是"禁止并行"，是**让每个文件只有一个写者**，于是并发不需要被禁止。

```
process/docs/
  units/
    u3-payment-retry/
      brief.md          # 制作人写：做什么、验收细则、预期触碰的文件集
      build.md          # 实现者写：本单元施工记录（汇总）
      build-part1.md    # 实现者的子代理写（同前缀不同后缀）
      build-part2.md
      accept.md         # 验收员写：逐条打勾的验收报告
  handoff/
    producer/index.md   # 制作人的接续索引
    implementer/index.md
    verifier/index.md
```

- **单元文件夹是传送带上的那件东西**：制作人交出 `brief.md` → 实现者写 `build.md` →
  验收员写 `accept.md` → 制作人读 `accept.md` 推进下一个单元。
- **子代理与同一角色的并发会话**：都写 `build.md` 就会撞车。各写 `build-part<N>.md`
  （同前缀不同后缀），再由该角色的下一次交接汇总进 `build.md`。
- **单元文件夹由第一个写它的人懒创建**，不需要预先建目录。
- `brief.md` 交出后不再改；要改就出 `brief-v2.md` 或追加 `brief.addendum.md`——
  否则实现者会基于过期视图施工。
- 实现者的施工记录里留一节「候选决策」：让"想记录"的冲动有正当出口，不必去写共享日志。

## 3. 归属与越界

**归属是路径的属性，不是比较出来的。**

- `units/u3/brief.md` 永远属于制作人。别人写了它，那叫**越界**，不叫"优先级低"。
- **不按时间判定**：后写覆盖先写会静默丢内容；"谁新谁赢"等于奖励越界者。
- **不设 `others/` 兜底目录**：两个"其他"会话会互撞在同一个 others 里，兜底还会把越界藏起来，
  而越界需要**可见**。没有角色的会话只有两种正当处理——给它一个角色，或它不与任何会话并行。

越界判定三步：

1. 路径在角色表里 → 归属明确，结束。
2. 路径不在表里 → 无人声明，不受保护；由制作人指定命名空间或并入自己的记录。
3. 路径属于别人 → 越界。规程：**内容保留**（不删）→ **位置修正**（移到越界者自己的
   命名空间，或标为提案）→ **由所有者裁决**是否采纳 → **记一次偏差**，供里程碑复盘。

> 判据：**若一件事需要靠"时间"或"来源"判断谁赢，说明命名空间设计错了。**

**模式切换不需要迁移文件**：单会话模式下写进共享文件的计划、日志、决策本来就归制作人，
路径不变，只是从"唯一写者"变成"角色表指定的写者"。

## 4. 降级：没用角色预设的会话

用户可能用自带的标准/PTC/创造/极简模式，或用自定义预设。本设计按**常态**处理这种情况，
四层降级，越往下越薄但不崩：

| 层 | 谁收到 | 承载什么 |
|---|---|---|
| 1 · persona | 只有角色预设 | 我是谁 + 我的写权 + 规则效力（系统提示词，永不被裁剪） |
| 2 · 项目 `AGENTS.md` | **任何预设**（注入层，压缩后会被恢复） | 效力声明 +「先确定角色」，并指向本文件 |
| 3 · 项目技能 | 标准/PTC/创造 | 触发与指针，不写正文（正文短到落在 4096 字头内） |
| 4 · 本文件 | 任何有文件工具的预设 | **唯一真源**：角色表、写权、读序、纪律 |
| 地板 | 极简模式 | 只剩 `AGENTS.md` 那两句；**极简模式不在支持范围**（它连文件工具都没有） |

所以"没装预设"的后果只是少一层权威：流程仍能走完，写权边界从系统提示词层降到文档层。

## 5. 流水线纪律

| 纪律 | 性质 | 破了会怎样 |
|---|---|---|
| 每个文件单写者 | **机制**（路径不重叠） | —— |
| 每角色独立接续点 | **机制**（写不同路径） | 旧结构下会静默丢信息 |
| 共享日志只有制作人写 | 约定 | 追加内容**静默丢失** |
| 一条流水线一个分支 | 约定 | 别人的文件视图被切走（可发现） |
| 按路径提交，禁止 `git add -A` | 约定 | 别人的半成品被卷进你的提交（事后可见） |
| 序列号只有制作人分配 | 约定 | `DECISION-XXX` / `ASSUMPTION-XXX` / `M-XXX` / `u<序号>` 撞号，**静默** |

- 「单写者」那两条靠布局生效，不需要谁守规矩；其余是约定，靠遵守与事后检查。
- 序列号交给制作人独占，不是因为它忙得过来，而是因为**实现者与验收员不做方向性决策**——
  他们的发现写在自己的单元文件里，由制作人判断哪些值得升格成 ADR。制作人是过滤器，不是瓶颈。
- 需要更硬的保障时，可按组级 `AGENTS.md` §6「重复动作脚本化」加检查脚本，
  不变量是「一次提交不得跨两个角色的命名空间」。**先写规范，真出现越界再上脚本。**

## 6. 会话接续（顺序固定，先定角色）

1. **先确定你的角色**：角色预设已给定就直接采用；没有就用提问卡片请用户指定
   （组级 AGENTS.md TOP 规则 3：请示一律用提问卡片）。
2. 读 `process/docs/HANDOFF.md`，按它写明的模式继续：
   - **单会话模式**：它就是接续点，接组级 `AGENTS.md` §7.4 的接续闸；
   - **多角色模式**：它只做静态路由，真正的接续点在 `process/docs/handoff/<你的角色>/index.md`
     → 读那里指出的最新一份交接文件。
3. 再读 `work-log` 尾 10 行 + `decisions` 索引 + `plans/plan.md` 当前段门禁表。

> 顺序不能颠倒：接续闸要读"你这个角色的接续索引"，角色未定就读不了。

## 7. 新增角色

项目级即可增补，**不必改组级规范**（组级非 TOP 条款是默认值，项目可在自己 `AGENTS.md` §2
登记）：条件是给它一个人手命名的、不与现有前缀重叠的命名空间，例如
`process/docs/handoff/researcher/` 与 `process/docs/units/*/research.md`。证明它有普遍价值后，
再按组级 `AGENTS.md` §9 回写本文件。

## 8. 硬约束：必须活到会话最后的规矩放哪

**一律进 persona，或进技能正文开头 4096 字以内；禁止放技能正文中段。**

理由是可验证的机制：标准模式的组合里挂着工具结果裁剪器，配置为超过 8192 字就压成
**头 4096 + 尾 1024**；技能正文是工具结果，写在**中段**的规矩会在长会话里被剪掉，
而注入的 `AGENTS.md` 在下一轮会被恢复——于是"通用的规矩一直在、角色的边界没了"，
表现就是"聊着聊着突然去写了别人的文件"。
