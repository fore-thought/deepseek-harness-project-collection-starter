# handoff（角色交接）· 每角色一份接续索引

> **只在多角色模式下使用。** 单会话模式的接续点就是 `../HANDOFF.md` 本身。
> 约定与越界规程见组级 `../shared-standards/pipeline-and-roles.md`（路径相对项目根）。

## 约定

- **每个角色一份索引**：`producer/index.md`、`implementer/index.md`、`verifier/index.md`。
  该角色的每一次交接都**新增**一份交接文件（不覆盖），索引里追加一行指向它。
- **索引由该角色自己维护**，别的角色只读。
- 交接文件名：`<角色>-<序号>-<YYYYMMDD>.md`，例如 `producer-03-20260916.md`。
- 格式参考 `../../templates/role-handoff.template.md`。

## 为什么不是一份共享的交接文件

一份文件是**单值**：两个会话同时收尾，后写的会覆盖先写的，先写那份的接续信息**永久丢失**。
拆成"每角色一份索引 + 每次新增一份文件"之后，每次交接都是新增，覆盖竞争从物理上消失。

## 接续时怎么读

1. 先确定你的角色（角色预设已给定，或用提问卡片问）；
2. 读 `../HANDOFF.md` 确认处于多角色模式；
3. 读 `index.md` 的**最后一行**指向的那份交接文件；
4. 再按技能 `project-flow` 里写的顺序读 work-log 尾 10 行、decisions 索引、plan 当前段。
